## Поведение

- Окно использует выданный API номер, masked phone и expiresAt. Обратный отсчёт
  пересчитывается по абсолютной дате, включая возврат из фоновой вкладки.
- PENDING не называется успешным входом. Ошибка HTTP/network или сохранённое
  PENDING-сообщение о недоступности проверки показаны внутри окна. Сырые
  provider/transport ошибки не подставляются в текст modal.
- По истечении срока номер и tel-действие скрываются. Пользователь видит
  окончание ожидания и может явно начать новую попытку. FAILED отличается от
  истёкшей проверки; terminal окно не исчезает с потерей объяснения.
- Новая попытка не стартует автоматически. Повторные быстрые нажатия блокируются;
  во время запроса прежний номер не предлагается. Ошибка повторного start остаётся
  видимой; новый номер может совпасть с предыдущим.
- «Войти через Telegram» доступно только при READY Telegram и сохранённом согласии.
  Действие переключает метод и запускает обычный Telegram start с подтверждением
  контакта. Оно не создаёт подтверждённую сессию самостоятельно.
- Закрытие окна не подтверждает вход; активную инструкцию можно снова показать.
  Native dialog изолирует фон, поддерживает Escape, Tab/Shift+Tab и возврат фокуса.

## Конкурентность и границы

Существующий status poll остаётся последовательным, раз в3секунды. Fetch и чтение
тела ограничены12секундами; start —15секундами. Проверка на границе expiresAt
может принять уже подтверждённый сервером результат. Номер при этом уже нельзя
набирать. После terminal состояния новые polls не запускаются.

Frontend generation и AbortController не дают позднему ответу прежней попытки
заменить новый метод/номер/клуб или вернуть старое окно. Abort не является
откатом уже выполненного серверного запроса; серверные idempotency/phone proof
и HttpOnly cookie остаются прежними. Только корректный серверный CONFIRMED
с portal продолжает существующий переход к выбору клуба.

Не менялись API/BFF routes, provider номер, TTL, JWT/cookie policy, tenant/store
scope, права, роли, фоновые задания, profile/reward/ledger данные. Клиентский
таймер не продлевает и не заменяет серверную проверку телефона.

## Проверка

Детерминированная local fake API fixture на127.0.0.1 проверяет настоящий
PlayRegistrationClient в Edge/Playwright, без production phone/token/challenge.
Сценарии: ожидание, сетевой сбой, HTTP200/PENDING provider-check failure,
истечение, retry и его ошибка, Telegram fallback и поздний ответ старого
звонка, недоступный fallback, клавиатура, desktop и mobile. В Node-регрессии
проверяются срок/форматирование, invalid timestamp, подтверждение на границе,
различие FAILED/EXPIRED и безопасные тексты. Тест добавлен в существующую
команду test:guest-session-transport; зависимости и lockfile не менялись.

Реальные звонки и естественный Telegram-вход пользователя не выполняются
в local fixture и требуют отдельной пользовательской проверки после rollout.
