# 06 — Отделить повтор запуска от устаревания остатков

Требования: R01, R02. Зона: `langame-daily-sync.service.ts` и его spec.

Фактический timer запускается раз в сутки в 04:30 Asia/Yekaterinburg. Пропуск INVENTORY при наличии success за последние 36 часов приводит к циклу 48 часов и 12-часовому окну STALE. Порог качества 36 часов остаётся в engine; использовать его для пропуска суточного обновления нельзя.

Пропуск в orchestration допускается только для недавнего успешного повторного AUTO INVENTORY по всем активным доменам в пределах 1 часа. Обычный следующий суточный запуск обновляет остатки. Исторический explicit-date canary по-прежнему не читает current goods; закрытый QUICK не переписывается; inventory не продвигает sales cursor.

Приёмка: два обычных запуска через 24 часа оба делают INVENTORY; повтор через 30 минут пропускает только при success всех доменов; один непокрытый домен требует обновления. Существующий engine freshness36h не меняется. Targeted daily tests, API build typecheck, scoped lint. Никаких production действий/таймеров/грантов/схем/новых env.
