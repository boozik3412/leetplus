# Контракт метрик дашборда ассортимента

Дата проверки источника: 2026-09-07. Основной внешний источник — публичный API Langame: <https://46.langamepro.ru/public_api/doc>.

## Правило отображения

Дашборд показывает число только тогда, когда его можно воспроизвести из сохранённых фактов. Если нет знаменателя, снимков остатков или достаточного числа клубов, API возвращает `null`, а интерфейс показывает «Нет данных». Нулевое значение используется только там, где ноль является результатом подсчёта, например при отсутствии товарных операций.

В текущем API Langame `GET /products/expense` одна запись содержит ID товарной транзакции, товар, количество, цену, клуб, гостя и смену. Идентификатора чека или заказа в ответе нет. Поэтому дашборд использует точную единицу **«товарная операция»** и не называет её чеком или покупкой.

## Метрики

| Показатель                   | Источник                                         | Формула                                                                       | Зерно                           | Условие показа                                                                           |
| ---------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------- |
| Визиты                       | `GuestSession`, `guests/sessions`                | `COUNT(DISTINCT session)`                                                     | игровая сессия                  | всегда; отсутствие сессий даёт 0                                                         |
| Товарные операции            | `SalesFact`, `products/expense`                  | `COUNT(non-cancelled sale operation)`                                         | строка продажи одного товара    | всегда; отсутствие операций даёт 0                                                       |
| Средняя сумма операции       | `SalesFact`                                      | `SUM(revenue) / COUNT(sale operation)`                                        | товарная операция               | только при наличии операций                                                              |
| Товарная выручка             | `SalesFact`                                      | `SUM(revenue)`                                                                | товарная операция               | всегда; отсутствие продаж даёт 0                                                         |
| Изменение к прошлому периоду | текущий и предыдущий периоды                     | `(current − previous) / previous × 100`; для коэффициента — разница в п.п.    | период той же длины             | только при ненулевой базе сравнения                                                      |
| Операций на 100 визитов      | `SalesFact` + `GuestSession`                     | `operations / visits × 100`                                                   | выбранный период                | только при наличии визитов                                                               |
| Идентифицированные гости     | `GuestSession`                                   | `COUNT(DISTINCT internal guest ID или provider + domain + external guest ID)` | гость                           | всегда; рядом показывается покрытие ID                                                   |
| Покрытие ID гостей           | `GuestSession`                                   | `identified visits / visits × 100`                                            | игровая сессия                  | только при наличии визитов                                                               |
| Сессий на гостя с ID         | `GuestSession`                                   | `identified visits / identified guests`                                       | идентифицированный гость        | только при наличии идентифицированных гостей                                             |
| Наличие активных SKU         | `InventorySnapshot` + `SalesFact`                | `(tracked active SKU − OOS-risk SKU) / tracked active SKU × 100`              | активный SKU со снимком остатка | только при наличии снимков остатков                                                      |
| Покрытие остатков            | `InventorySnapshot`                              | `tracked active SKU / active SKU × 100`                                       | активный SKU                    | только при наличии активных SKU                                                          |
| Товаров в операции           | `SalesFact`                                      | `SUM(quantity) / COUNT(sale operation)`                                       | товарная операция               | только при наличии операций                                                              |
| Средняя цена товара          | `SalesFact`                                      | `SUM(revenue) / SUM(quantity)`                                                | проданная единица               | только при положительном количестве                                                      |
| Категория-лидер              | `SalesFact` + `Product.category`                 | категория с максимальной `SUM(revenue)`                                       | категория                       | только при наличии продаж                                                                |
| Покрытие себестоимости       | `SalesFact`                                      | `operations with positive cost / sale operations × 100`                       | товарная операция               | только при наличии операций                                                              |
| Маржа товаров                | `SalesFact`                                      | `(SUM(revenue) − SUM(cost)) / SUM(revenue) × 100`                             | товарная операция               | только при положительной выручке и 100% покрытии себестоимости                           |
| Потенциал клуба              | `SalesFact` + подтверждённая общая выручка клуба | `club revenue × (median product share − club product share)`                  | клуб                            | минимум два клуба; источник общей выручки — операции или транзакции, не товарная выручка |

OOS-риск считается только для активных SKU со снимком остатка. Активный SKU — позиция с положительным текущим остатком или продажей за последние 14 дней. Спрос для OOS оценивается по продажам за 21 день. Отсутствующий снимок больше не трактуется как нулевой остаток.

## Фильтры и сравнение

- Период и клуб применяются ко всем фактам.
- Категория применяется к продажам, остаткам, движениям и товарной части расчётов.
- Визиты остаются общим трафиком выбранных клубов: у игровой сессии нет категории товара.
- Изменение сравнивается с предыдущим периодом той же длины. Если предыдущий знаменатель равен нулю, процент изменения не показывается.
- Идентификаторы сессий и гостей учитывают провайдера и домен источника, чтобы одинаковые внешние ID разных подключений не склеивались.

## Что потребуется для настоящего среднего чека

Нужен стабильный `receipt_id` или `order_id`, одинаковый для всех товарных строк одного чека и доступный для исторической загрузки. После появления поля контракт можно расширить без эвристик:

1. сохранить внешний ID чека у каждой записи `SalesFact`;
2. проверить покрытие и уникальность по провайдеру, домену и клубу;
3. считать чеки как `COUNT(DISTINCT receipt_id)`;
4. считать средний товарный чек как `SUM(product revenue) / COUNT(DISTINCT receipt_id)`;
5. считать товары в чеке как `SUM(quantity) / COUNT(DISTINCT receipt_id)`.

`middle_check` из смен и фискальный номер из журнала операций не используются как замена: первый не поддерживает фильтр категории и произвольный период, а второй сейчас не имеет надёжной связи с каждой строкой `products/expense`.
