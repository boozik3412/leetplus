# Контракт метрик дашборда ассортимента

Дата проверки источника: 2026-09-08. Основной внешний источник — публичный API Langame: <https://46.langamepro.ru/public_api/doc>.

## Правило отображения

Дашборд показывает число только тогда, когда его можно воспроизвести из сохранённых фактов. Если нет знаменателя, снимков остатков или достаточного числа клубов, API возвращает `null`, а интерфейс показывает «Нет данных». Нулевое значение используется только там, где ноль является результатом подсчёта, например при отсутствии товарных операций.

В текущем ответе Langame `GET /products/expense` для production-источника одна запись содержит ID товарной транзакции, товар, количество, цену, клуб, гостя и смену, но не содержит ID чека. Поэтому базовая метрика остаётся точной единицей **«товарная операция»**. Если источник начинает отдавать `receipt_id`, `order_id`, `check_id` или `sale_check_id`, синхронизация автоматически связывает строки одного чека. Тот же ID можно передать колонкой «Чек» в CSV продаж.

Идентификатор чека не хранится и не возвращается в открытом виде. Перед сохранением он нормализуется и хешируется SHA-256, а полученный receipt-bound token связывается с хешем исходной строки. Это позволяет считать чеки и товарные пары без раскрытия номера чека. При частичном покрытии интерфейс явно показывает процент операций и выручки, на которых основан результат.

## Метрики

| Показатель                   | Источник                                            | Формула                                                                       | Зерно                           | Условие показа                                                                           |
| ---------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------- |
| Визиты                       | `GuestSession`, `guests/sessions`                   | `COUNT(DISTINCT session)`                                                     | игровая сессия                  | всегда; отсутствие сессий даёт 0                                                         |
| Товарные операции            | `SalesFact`, `products/expense`                     | `COUNT(non-cancelled sale operation)`                                         | строка продажи одного товара    | всегда; отсутствие операций даёт 0                                                       |
| Средняя сумма операции       | `SalesFact`                                         | `SUM(revenue) / COUNT(sale operation)`                                        | товарная операция               | только при наличии операций                                                              |

| Идентифицированные гости     | `GuestSession`                                      | `COUNT(DISTINCT internal guest ID или provider + domain + external guest ID)` | гость                           | всегда; рядом показывается покрытие ID                                                   |
| Покрытие ID гостей           | `GuestSession`                                      | `identified visits / visits × 100`                                            | игровая сессия                  | только при наличии визитов                                                               |
| Сессий на гостя с ID         | `GuestSession`                                      | `identified visits / identified guests`                                       | идентифицированный гость        | только при наличии идентифицированных гостей                                             |
| Наличие активных SKU         | `InventorySnapshot` + `SalesFact`                   | `(tracked active SKU − OOS-risk SKU) / tracked active SKU × 100`              | активный SKU со снимком остатка | только при наличии снимков остатков                                                      |
| Покрытие остатков            | `InventorySnapshot`                                 | `tracked active SKU / active SKU × 100`                                       | активный SKU                    | только при наличии активных SKU                                                          |
| Товаров в операции           | `SalesFact`                                         | `SUM(quantity) / COUNT(sale operation)`                                       | товарная операция               | только при наличии операций                                                              |
| Средняя цена товара          | `SalesFact`                                         | `SUM(revenue) / SUM(quantity)`                                                | проданная единица               | только при положительном количестве                                                      |
| Категория-лидер              | `SalesFact` + `Product.category`                    | категория с максимальной `SUM(revenue)`                                       | категория                       | только при наличии продаж                                                                |
| Покрытие себестоимости       | `SalesFact`                                         | `operations with positive cost / sale operations × 100`                       | товарная операция               | только при наличии операций                                                              |
| Маржа товаров                | `SalesFact`                                         | `(SUM(revenue) − SUM(cost)) / SUM(revenue) × 100`                             | товарная операция               | только при положительной выручке и 100% покрытии себестоимости                           |
| Потенциал клуба              | `SalesFact` + подтверждённая общая выручка клуба    | `club revenue × (median product share − club product share)`                  | клуб                            | минимум два клуба; источник общей выручки — операции или транзакции, не товарная выручка |
| Покупки                      | receipt-bound token в `SalesFact.sourcePayloadHash` | `COUNT(DISTINCT provider + domain + store + SHA-256(receipt ID))`             | чек или заказ                   | только при наличии ID чека; при частичном покрытии показывается статус                   |
| Средний товарный чек         | строки с receipt-bound token                        | `SUM(covered revenue) / COUNT(DISTINCT receipt)`                              | чек или заказ                   | только по покрытой части                                                                 |
| Товаров в чеке               | строки с receipt-bound token                        | `SUM(covered quantity) / COUNT(DISTINCT receipt)`                             | чек или заказ                   | только по покрытой части                                                                 |
| Частая пара товаров          | строки с receipt-bound token                        | самая частая неупорядоченная пара разных товаров внутри одного чека           | чек или заказ                   | минимум один чек с двумя разными товарами                                                |
| Прогноз товарной выручки     | `SalesFact` за окно 28 календарных дней             | среднее по подтверждённым дням продаж того же дня недели; fallback — среднее  | следующие 7 дней                | не показывается без истории; до 14 дней или при проблемах источника — предварительный    |
| Выручка под риском OOS       | `InventorySnapshot` + спрос 21 дня + цена           | `MAX(0, спрос 7 дней − остаток) × цена продажи`                               | активный SKU                    | только для SKU со снимком остатка и положительным спросом                                |
| Эффект пополнения            | прогноз дефицита + кратность поставщика             | `MIN(выручка под риском, рекомендуемый заказ × цена)`                         | активный SKU                    | только для SKU с вычислимым дефицитом                                                    |

OOS-риск считается только для активных SKU со снимком остатка. Активный SKU — позиция с положительным текущим остатком или продажей за последние 14 дней. Спрос для OOS оценивается по продажам за 21 день. Рекомендуемый заказ закрывает ожидаемый спрос следующих 7 дней и округляется с учётом кратности поставщика. Отсутствующий снимок не трактуется как нулевой остаток.

## Контроль качества и действия

Дашборд отдельно показывает свежесть визитов, продаж, остатков, себестоимости и категорий. Статусы `FRESH`, `STALE`, `MISSING`, `FAILED` и `PARTIAL` вычисляются по последнему факту, времени загрузки, результату синхронизации и покрытию. Порог устаревания — 36 часов. Ошибка последней синхронизации имеет приоритет над частичным покрытием.

Если продажи есть, а визитов за тот же период нет, метрики конверсии получают состояние `SOURCE_CONFLICT` и не рассчитываются. Блок «Что сделать сегодня» собирается только из воспроизводимых сигналов и ведёт в существующие рабочие отчёты:

1. восстановить источники или загрузку визитов;
2. пополнить SKU с прогнозируемым дефицитом;
3. заполнить отсутствующую себестоимость;
4. назначить и нормализовать категории;
5. догрузить отсутствующие снимки остатков;
6. поднять товарную конверсию клуба ниже медианы сети, если более срочных проблем меньше пяти.

На экран выводятся первые пять действий по приоритету. Денежный эффект показывается только там, где его можно вывести из сохранённых продаж, цен и остатков.

## Фильтры и сравнение

- Период и клуб применяются ко всем фактам.
- Категория применяется к продажам, остаткам, движениям и товарной части расчётов.
- Визиты остаются общим трафиком выбранных клубов: у игровой сессии нет категории товара.
- Изменение сравнивается с предыдущим периодом той же длины. Если предыдущий знаменатель равен нулю, процент изменения не показывается.
- Идентификаторы сессий и гостей учитывают провайдера и домен источника, чтобы одинаковые внешние ID разных подключений не склеивались.

## Покрытие чековых метрик

Для production-источника без `receipt_id` или `order_id` карточки покупок, среднего чека и товаров в чеке показывают состояние `SOURCE_UNAVAILABLE`. После появления поля в Langame оно подхватится без изменения схемы базы и начнёт накапливать покрытие со следующей синхронизации. Историю можно дополнить CSV с колонкой «Чек».

`middle_check` из смен и фискальный номер из журнала операций не используются как замена: первый не поддерживает фильтр категории и произвольный период, а второй сейчас не имеет надёжной связи с каждой строкой `products/expense`.
