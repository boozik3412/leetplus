## Редакторы и контракты условий

- Задания создаются и редактируются только через мастер v2; старый редактор заданий скрыт.
- Три шага мастера: `Условия -> Награды -> Внешнее оформление`.
- Мастер поддерживает бессрочность, периодичность, лимиты, XP/«Не начислять», бонусы Langame, промокоды, наградные лутбоксы, отсутствие основной награды, ручную/автоматическую выдачу, темы и live-preview.
- Типы заданий: `APP_OPEN`, `PLAY_TIME`, `PRODUCT_PURCHASE`, `BALANCE_TOPUP`, `CHECK_IN`.
- Battle Pass использует те же семейства условий, что мастер заданий.
- Лутбоксы поддерживают тип сессии `ANY`, `HOURLY`, `PACKAGE_OR_SUBSCRIPTION`.
- Неизвестный тип сессии подходит только `ANY`; его нельзя угадывать как почасовой или пакетный.
- Категории Langame и LeetPlus — разные источники. Одинаковое название не объединяет их автоматически.
- Покупки поддерживают товары/категории, `ANY/ALL`, отдельную минимальную и накопительную сумму. Покупка учитывается только при привязанном госте; отмены и возвраты не должны засчитываться.
- Точные тарифные справочники пока не подтверждены structured-источником и остаются `В разработке`.

## Источники выполнения условий

| Условие | Текущий источник |
| --- | --- |
| Вход в игровой модуль | Прямой LIVE `APP_OPEN`; Ledger не подменяет его |
| Старт сессии | LIVE session/snapshot; возможен последовательный `LIVE_WITH_LEDGER_FALLBACK` |
| Наигранное время | LIVE session/snapshot; возможен fallback по завершённым Ledger-фактам |
| Покупки | LIVE product expense; Ledger пока только SHADOW |
| Пополнение баланса | `LEDGER_SUPPLEMENTAL` по `BALANCE_TOPUP` |
| Чекин | Отдельный LIVE check-in pipeline |

- `LIVE_WITH_LEDGER_FALLBACK` ждёт grace-период и сначала ищет LIVE-событие. Только при его отсутствии он создаёт каноническое восстановление через общий evaluator/reward pipeline.
- `SHADOW` никогда не создаёт event, XP, wallet item, entitlement или reward.
- `APP_OPEN` и чекин нельзя заменять generic session/visit-фактами.
- Наличие кода fallback/supplemental не означает, что режим включён. Проверять runtime env/status, tenant scope, cutoff, allow-list, lag, retries/dead letters и `/gamification/log`.

## Награды, кошелёк и модальные окна

- Выполнение миссии, Battle Pass, чекина или event-сценария квалифицирует обычную награду и XP как отдельные wallet item.
- Обычная награда/XP применяются после явного `Забрать`; `claim-all` не открывает лутбоксы.
- Лутбокс создаёт entitlement. Случайный приз определяется только после ручного `Открыть контейнер`.
- Полученное entitlement не исчезает после окончания исходного временного окна/сессии.
- `REWARD_TEMPLATE` используется только как наградной контейнер миссии/Battle Pass и не показывается как самостоятельный кейс в каталоге.
- Completion-уведомления миссии/Battle Pass хранятся в БД и считаются просмотренными только после явного подтверждения. После reload неподтверждённое окно возвращается.
- ACK поздравительной модалки — read-only: он не является claim и не создаёт повторную награду.
- `/game/rewards` и reward history сохраняют доступ к ожидающим и завершённым результатам.
- Неоднозначный результат внешней записи Langame переводится в `RECONCILIATION_REQUIRED` без автоматического retry.

## Авторизация гостя

- Канонический поток: `/game/auth -> подтверждение Telegram/звонком -> /game/clubs -> /game`.
- После выбора клуба первый trusted `APP_OPEN` задаёт `GuestGameProfile.gameActivatedAt`; более ранние факты не backfill-ятся в игровой прогресс.
- При `401` или истёкшей guest-сессии `/game` и `/game/rewards` отправляют на повторный вход `/game/auth`.
- Network/timeout/5xx показываются как повторяемая техническая ошибка, а не как истёкшая авторизация.
- Telegram/call resume должен продолжать тот же handoff идемпотентно, без второго профиля или повторного referral event.
- Устаревшие Langame-привязки обновляет автоматический domain-scoped resolver по подтверждённой идентичности. Неоднозначное совпадение завершается без привязки.

## Диагностика

- Главная точка расследования: `/gamification/log`.
- Для каждого сбоя проверять: правило и его версию, статус/активацию, клуб/domain, источник факта, freshness, LIVE/SHADOW decision одного evaluation run, matched fact IDs, progress, origin receipt, reward intent/effect, wallet, entitlement и bonus ledger.
- Для Battle Pass дополнительно проверять текущий шаг и последовательность предыдущих шагов.
- Для лутбокса различать `условие выполнено`, `entitlement доступен`, `контейнер открыт`, `приз создан`.
- Для check-in streak день считается в timezone клуба; уже реализованный алгоритм использует уникальные локальные даты и обнуляет серию после пропущенного календарного дня.
