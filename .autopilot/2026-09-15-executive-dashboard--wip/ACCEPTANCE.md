# Приёмка v2: ожидаемый результат до действия

Это план проверок, не отчёт о пройденном UI. Сейчас все сценарии NOT_RUN. Матрица ограничена изменяемыми компонентами; не перемножать все роли/темы/состояния бессмысленно.

## Детерминированная аналитическая выборка

Фикстура, не production. КлубA: услуги8000, товары2000, выручка10000, визиты20; клубB: услуги18000, товары12000, выручка30000, визиты300. Источники полные, суммы непересекающиеся, отмены проверены. Пополнение3000 учитывается отдельно.

Для A+B ожидается: выручка40000; товарная14000; визиты320; доход на визит125; доля бара35%. Среднее клубных доходов300 и среднее долей30% неверны. Третий недоступный клуб с большой суммой не меняет результат.

Отдельная фикстура мощности: A занят100ч из200ч, B занят150ч из1000ч. Сеть250/1200=20,833…%, а не среднее50% и15%=32,5%. Часы и режим в этом тесте подтверждены; он не разрешает предполагать такие данные в production.

## Уровни доказательства

1. Source/unit/integration подтверждает расчёты и scope, но не рендер.
2. Реальное приложение на deterministic fixture подтверждает поведение UI с ожидаемыми результатами. Отдельный HTML-макет его не заменяет.
3. Разрешённая реальная сессия проверяется отдельно; обычная авторизация, без поддельногоJWT, измененияролей или массовыхэффектов.
4. Production deployment — отдельный exact release процесс. Зелёныйлокальныйтестили4/4валидацииупаковкинавыковего не доказывают.

В доказательстве фиксируются checkout/SHA, среда,роль,выборка,ожидание,фактическийрезультат, URL/скриншотиливывод. Секреты иперсональныеданные не сохраняются. Недоступное помечается NOT_RUN/SKIPPED/BLOCKED с причиной. Старые55проверок HTMLостаютсяисториеймакетов.
