# 0007. Отделять свежесть данных от подавления AUTO-повтора

## Контекст

Дата решения: 14.09.2026. D09: ежедневный timer в 04:30 Asia/Yekaterinburg вместе с подавлением INVENTORY на 36 часов создаёт цикл в 48 часов и окно устаревания.

## Решение

Порог freshness данных остаётся 36 часов, а orchestration подавляет только успешный недавний AUTO-повтор по всем доменам в пределах одного часа.

## Почему

Отклоняется использование 36-часовой freshness как периода подавления ежедневного запуска: следующий штатный запуск тогда пропускается, хотя качество данных ещё не является критерием повтора. Это регулярно откладывает обновление до 48 часов.

## Последствия

Каждый обычный суточный запуск снова обновляет inventory, если нет успешного AUTO-повтора за последний час по всем доменам. Новые timers, env или полномочия не вводятся; оценка свежести в engine не меняет свой 36-часовой порог.
